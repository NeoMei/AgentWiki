目标：在同一 Space 中连续浏览目录、阅读文章和编辑文章，清楚知道当前页面所在位置。

本轮只调整前端结构、呈现和导航状态。Space / Folder / Page 模型、权限事实源、Agent 绑定、协作审核、版本与冲突处理、同步协议和目录修订校验均不变。目录顺序使用现有服务端结果；不从路径构造虚拟 Folder，不让 Folder 承载正文。

## 1. 稳定的工作区

- 保留全局导航和现有空间功能导航，原有目的地可继续访问。
- 左侧为当前空间目录，桌面初始宽度约 260px。阅读与编辑使用同一个目录区域。
- 右侧为内容区，正文居中，阅读与编辑的正文宽度尽量一致。
- 内容区顶部固定位置呈现面包屑与页面动作，滚动正文时仍能找到主要操作。
- 页面标题位于正文上方；编辑时在原位置变为标题输入框。
- 桌面以舒适正文行宽为目标，长代码和表格在内容区内横向滚动。
- 来源与变更、版本等通过“页面信息”入口访问；待处理冲突、保存失败和必要审核提醒仍在正文附近清楚展示，不藏入面板。

## 2. 目录交互

| 用户操作 | 呈现结果 | 数据边界 |
|---|---|---|
| 点击文件夹箭头 | 展开或收起子节点，不替换正在阅读的正文 | 按需调用现有子节点列表接口 |
| 点击文件夹名称 | 选中该目录；内容区展示该层的现有子目录、页面列表 | 列表是目录内容视图，不新增目录正文 |
| 点击页面名称 | 内容区打开页面，左侧高亮该页 | 沿用页面 ID 与既有访问权限 |
| 进入另一页 | 保留目录展开与左侧滚动状态，按需要让选中项可见 | 仅前端浏览状态 |
| 点击面包屑父目录 | 展示该目录内容，并在左侧定位 | 不修改真实目录关系 |
| 点击新建 | 使用既有创建流程，明确显示目标目录 | 仍按服务端权限和修订校验创建 |
| 点击行尾更多 | 展示该节点已有的适用操作 | 不扩大权限，不增加新业务动作 |

新建目标：选中文件夹时为该文件夹；选中页面时为页面所在文件夹；空间根视图则为根目录。弹窗始终显示位置，不能只靠隐式选中状态推断。

保留现有移动能力和删除影响确认。拖拽、重命名等操作失败时保留原有错误与重试路径；不能先把本地树当作成功落库的事实。

长标题默认单行截断，并提供可获取完整标题的提示；选中状态同时用浅底、图标和文本强调。更多操作在键盘聚焦时可见；触屏不依赖悬停。目录树支持可识别的层级、展开状态和键盘导航。

目录按需加载，不一次拉取整个 Space。展开失败在对应节点显示重试，不能误显示为无子项。不能将不同修订的数据直接当成同一份可靠树快照；重新加载或提示按既有冲突策略执行。

左侧搜索图标第一阶段复用已有搜索入口。未证实支持空间过滤之前，不承诺新增“空间内全文搜索”。此项不阻塞核心目录与正文布局。

## 3. 阅读状态

- 打开页面默认阅读；标题、现有作者/更新时间按实际字段显示。
- 主要动作是文字按钮“编辑”；无编辑权限时不提供可编辑入口。
- “页面信息”打开按需侧面板，呈现已有来源、变更及相关入口；内容区不永久预留来源栏。
- 删除、模板、Agent 相关操作按现有适用条件组织在更多菜单或页面信息中。
- 没有自动化来源的人工页面不常驻一整块空来源区域。
- 相关页面与证据信息保留，本轮不修改其数据含义、排序或关系模型。

本文目录默认收起，入口固定在内容区右上角工具栏，使用目录图标和“本文目录”文字。采用用户指定的 Codex Desktop 式右上角浮窗交互：点击后在按钮下方、靠右对齐展开，覆盖在正文上方，不增加固定侧栏，不改变正文宽度；移除选中草图标题下方的通栏目录折叠条。左侧空间目录保持原位。

浮窗使用当前组件体系的 Popover：约 280px 宽，细边框、轻阴影，标题为“本文目录”；按照正文标题层级缩进，当前章节轻高亮，长目录限制高度并在浮窗内部滚动。用户点击标题后定位对应段落并收起浮窗；再次点击入口、点击浮窗外或按 Escape 可关闭。浮窗与触发按钮保持锚定，正文滚动时入口仍可用；键盘关闭后焦点回到触发按钮。没有可导航标题时隐藏入口，不显示空浮窗。视觉沿用 AgentWiki，不复制 Codex 的品牌或全局主题。

本文目录由现有 Markdown 解析/渲染所得标题派生，复用现有锚点规则；不修改原文，不将代码块里的井号误判为标题，不新建目录字段。

## 4. 编辑与预览状态

| 状态 | 主要动作 | 行为 |
|---|---|---|
| 阅读 | 编辑、页面信息、更多 | 进入编辑时保持目录与页面位置 |
| 编辑且无修改 | 保存禁用、预览、返回阅读 | 标题和正文在同一内容区编辑 |
| 编辑且有修改 | 保存、预览、返回阅读 | 显示未保存状态；保存继续使用现有接口 |
| 保存进行中 | 保存中 | 禁止重复保存，不把请求完成前视为成功 |
| 保存成功 | 已保存 | 留在编辑状态；不自动退出编辑 |
| 编辑器预览 | 返回编辑、保存（按修改状态启用） | 展示当前编辑缓冲内容；切换本身不保存 |
| 保存失败或冲突 | 现有错误/冲突处理入口 | 保留本地内容，不覆盖远端，不悄悄关闭提示 |

编辑/预览保持互斥的单内容区。现有 Markdown 工作区、图片附件、编辑辅助、版本历史和协作能力继续复用，不更换编辑器。

“返回阅读”离开编辑会话，和“预览”含义不同。存在未保存修改时，包括点击目录、面包屑、空间导航、版本入口和关闭页面在内，都要走未保存保护；取消离开后正文、目录选中项及编辑缓冲不变。确认放弃只影响本地未保存修改，不回滚服务器内容。

保存时发生新输入，成功提示只代表该次提交的内容已保存，后续输入继续保持未保存状态；沿用现有编辑修订检查。

读写模式切换尽量恢复同一段落或编辑光标附近，而不是只复制两种排版下的像素滚动值。普通首次打开另一篇文章从顶部开始；浏览器返回恢复离开前位置。

## 5. 小屏与边界状态

当并排显示会挤压正文时，将空间目录切换为抽屉，保持正文为单列；本文目录仍从右上角按需展开，浮窗宽度受屏幕左右安全边距约束。页面动作优先保留编辑/保存文字，其余进入更多菜单。

- 空间空目录：展示清楚的空状态，仅向有权限者提供创建入口。
- 页面加载失败：内容区提供重试，目录仍可用于访问其他页面。
- 深链接进入页面：按真实 Folder 关系恢复面包屑与目录定位；恢复中显示定位状态，不能猜测祖先目录。
- 页面被移动/删除或访问权限变化：按服务端实际结果更新树与内容区，不能长期显示缓存的可编辑状态。
- 所有新增界面文案通过现有中英文语言上下文，沿用语言持久化规则。

## 6. 前端复用与实施前检查

工作区布局负责共用目录、面包屑和内容槽位；现有 SpaceView、PagePreview、PageEditor 逐步接入这一布局。布局不接管权限判断、保存事务或审核决策。现有 URL 保持可访问，刷新、深链接、历史版本链接不得失效。

已经从当前源代码核对：
- contentTreeApi.listTreeChildren 支持按 parentFolderId 分层、分页读取。
- 目录移动/更名等仍携带 expectedTreeRevision、expectedUpdatedAt。
- PageEditor.handleSave 使用现有页面 PATCH，正文保存携带 expectedUpdatedAt；标题变化额外取得目录修订。
- 保存成功更新编辑基线，不自动切换阅读；保存过程中后续输入继续保持 dirty。

当前已核对：现有 GET /spaces/:spaceId/folders 返回目录及 parentId，可作为深链接祖先恢复的数据来源；结合页面 folderId 与分层 content-tree 请求，恢复对应祖先与同级节点。实施中验证分页、树修订一致性及权限变化；不从 path 文本猜测父子关系。全局搜索先复用既有入口，不新增空间过滤承诺。若出现现有读能力无法覆盖的事实，单独说明最小补充方案并取得确认；不得改变后台模型和写入语义以配合界面。

## 8. 已确认的相关子页面范围

核心联动：Space 根目录、文件夹内容视图、文章阅读、编辑与预览，共用工作区和导航状态。

配套衔接：现有版本历史及版本预览弹窗、新建页面/文件夹、移动与改名交互、页面信息，统一操作对象、目标目录和返回上下文。当前没有独立版本对比页面，本轮不新增对比能力。历史页可以收起目录以便阅读，返回文章恢复原状态；版本恢复仍调用原流程并进入既有编辑目的地。

外框统一：图谱、来源、运行记录、协作、成员、设置及现有空间内下级配置/运行页面，统一空间标题、导航和返回入口；内部业务布局与操作不重做，不强制挂文章目录。

入口兼容：搜索、审核和图谱中的页面链接验证深链接定位；不重做全局搜索、审核、智能体、登录、账户或公共使用指南页面。

本轮不加入空间介绍页配置、置顶/收藏、最近浏览、新排序机制、全新搜索或后台重构。布局中保留现有能力入口即可。

## 7. 验收标准

1. 从多层文件夹打开页面后，同级页面和祖先位置仍清楚可见。
2. 连续切换三篇文章，目录展开和左侧滚动状态稳定。
3. 长文能在页首及阅读中途使用本文目录定位，锚点与现有链接兼容。
4. 阅读、编辑、预览切换保持稳定布局及合理正文位置。
5. 保存仍留在编辑状态；预览不触发保存；新输入不被一次较早的保存错误标记为已保存。
6. 未保存时切页、选目录或返回阅读，取消离开能完整恢复原上下文。
7. 在指定目录创建、移动、改名、删除时复用原有目标、权限和修订检查。
8. 只读、无权限、409 冲突、远端修改、附件与编辑辅助的既有规则不退化。
9. 手机目录抽屉、键盘操作、长标题、中英文、刷新和深链接均覆盖真实浏览验证。
10. 后台模型、写入接口语义和同步协议没有因本轮呈现改造而变化。

这些是未来实施的验收条件；当前仅核对源代码和设计，不声称已通过上述验收。

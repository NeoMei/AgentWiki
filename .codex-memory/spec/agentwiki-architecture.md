# AgentWiki stable architecture rules

- React/Vite + React Router is the only current frontend baseline; NestJS + Prisma/PostgreSQL is the backend baseline.
- Global IA: Spaces, Agents, Review, Search and a personal menu containing Profile/Integrations/Guide/About. Space IA: Pages, Graph, Sources, Runs, Members, Settings.
- Human JWT/PAT and AgentCredential are distinct identities. JWT/WebSocket authentication rechecks the current non-deleted human User. Agent access uses exactly `reader`、`editor`、`publisher`; `AgentGrant.role` is the sole persisted permission fact, each AgentCredential binds exactly one same-Agent Grant, and scopes are derived live from that Grant. Authorization also checks Credential/Agent/owner state, Space policy and domain rules. Agents never receive `review:decide` or member-management permission.
- Human users have a separate `platformRole`; `super_admin` is reloaded from PostgreSQL on every JWT/PAT authentication, can read every active Space; without a real Space membership it has viewer capabilities only and cannot mutate content, graph, sources, review, bindings, members, or Space configuration. A platform administrator who is a Space member follows that membership role, including domain-specific restrictions. Central checks and live transaction checks must both enforce this rule. Agent credentials never inherit their owner's platform role, and private Agent memory ownership checks remain in force.
- Source → SourceVersion → IngestRun → Artifact/Evidence → ChangeSet/Approval → Page/Relation is the canonical knowledge-production chain.
- Confirmed OKF re-sync tracks Source accepted head plus a monotonic generation, pins each Run to both, and gives Pages a reviewed generation only through server-validated human publication. Identical version content reused after A→B→A is a new generation; durable idempotency receipts, including noop, cannot roll the accepted head back. Worker processing never advances that head.
- Source freshness is an authorized projection of the exact returned Page snapshot: untracked / unknown / unavailable / needs_review / current. Current means review alignment, not truth; historical nulls never imply current. Source access denial removes identifiers, run provenance and evidence while retaining an otherwise authorized Page body. Historical evidence uses a minimum field allowlist.
- Actual body/format/source-link edits clear reviewed generation; identical content and title/placement-only edits preserve it. PageVersion restore cannot recreate a review proof. Exact ChangeSet revert restores its recorded before generation, without moving Source head. Archived Sources preserve authorized history and accepted head, block processing/publication, and activation does not increment generation.
- Unified gateway read tools support named parameters and compatible legacy __args, retain explicit Space routing and live credential checks. Gateway stdio exposes tools; server /api/mcp also supports page resources. Tool usability, actual model answer quality, UI acceptance, and deployment are separate evidence claims.
- Agent memory is scoped by Space; private memories are limited to the target Agent while explicitly shared memories are visible to authorized Agents in that Space. Only episodic and semantic types are claimed. Recall explanations expose lexical, persisted-embedding (with trigram fallback), actual knowledge-graph and importance signals.
- Remote MCP uses Streamable HTTP at `/api/mcp`, Host allowlisting and the same service-layer authorization. Agents cannot approve change sets.
- Agent REST and MCP content writes both enter ChangeSets; only accepted items publish. Page/relation create, update and archive changes preserve prior state, reject stale candidates and support rollback.
- Page and Relation retain origin provenance separately from the latest modifier. Published page changes synchronously maintain `PageSearchDocument`; semantic embedding is optional enrichment.
- API and ingestion Worker are separate process roles. Workers use renewable fenced leases, periodically reclaim only expired work, and re-check the current requesting credential/authorization at multiple stages.
- The remote application uses direct Node.js deployment, not Docker: user-level systemd separately supervises API, ingestion Worker and the Vite production frontend. Releases require verified PostgreSQL custom-format and application rollback backups before source replacement or Prisma deploy, mirror source to remove stale files, explicitly regenerate Prisma Client before building, and require `/api/health` plus business smoke checks.
- API and Worker production module graphs must each compile in automated Nest tests; TypeScript compilation alone is not a sufficient deployment gate.
- Legacy `/spaces/:id/docs` only redirects to Sources for compatibility; legacy backend code/models are removed and historical jobs are migrated to Source/Run records.

## 记录

- 日期：2026-07-15

- 日期：2026-07-15
- 决定：Agent 使用独立领域实体，由人类用户拥有；知识仍以 Space 为隔离边界。
- 原因：避免把 Agent 等同于可登录人类用户，也避免重复创建第二套知识库模型。
- 影响范围：Agent、API Key、授权、审计、记忆、MCP。

- 日期：2026-07-15
- 决定：自动生成内容先形成可审查变更，再发布为正式页面；来源证据贯穿摄取、关系、页面和审批。
- 原因：保证 Agent 写入可追溯、可拒绝、可回滚。
- 影响范围：摄取、编译、审批、页面、图谱。

- 日期：2026-07-15
- 决定：旧 DocumentGeneration HTTP 模块下线，旧 UI 路由重定向 Sources，历史任务迁移到 Source/Run。
- 原因：避免绕过统一来源、证据和审批链。
- 影响范围：AppModule、React Router、Prisma 数据迁移。

- 日期：2026-07-15
- 决定：MCP 使用稳定 v1 SDK 的 Streamable HTTP；SDK 深层泛型封装在适配层，避免拖慢应用声明构建。
- 原因：当前 v2 SDK 仍为预发布，v1 是稳定推荐；协议边界不应污染领域层类型推导。
- 影响范围：MCP 模块、构建性能、接入指南。

- 日期：2026-07-15
- 决定：Agent 经 REST 或 MCP 的页面/关系写入都必须形成 ChangeSet；不支持安全候选类型的删除、恢复或关系强度修改直接拒绝。
- 原因：避免协议通道不同导致 Agent 绕过默认审批。
- 影响范围：Page/Knowledge Controller、Review 发布与回滚、权限回归测试。

- 日期：2026-07-15
- 决定：生产 API 固定 `PROCESS_ROLE=api`，摄取由无 HTTP 监听的独立 Worker 执行；Worker 执行前重验请求者授权。
- 原因：隔离耗时和不可信来源处理，并避免排队后撤权仍继续执行。
- 影响范围：IngestQueue、WorkerModule、部署运维、审计。

# AgentWiki 文档体验：OpenKnowledge 借鉴分析与改造建议

日期：2026-10-06（Asia/Shanghai）。状态：调研结论与设计建议，尚未实施产品改造。

## 结论

值得借鉴，尤其是连续的文档工作区、可发现的目录操作、可视编辑和有上下文的 Agent 修改。建议采用“先完善现有工作区，同时验证可视编辑器，再扩展人和 Agent 的精确协作”的路线。

AgentWiki 已有 CodeMirror 6 实时预览、目录拖拽、阅读大纲、版本检查、附件解析和提案权限。应保留这些能力，重点补齐读写排版一致性、就地操作、草稿恢复和候选差异审阅。仅改颜色和圆角不够；直接替换整套编辑器也会把 Markdown 保真和同步风险带进来。

## 先区分两个借鉴对象

用户给出的 `/docs/` 是说明文档网站。源码 [`docs/src/app/docs/layout.tsx`](https://github.com/inkeep/open-knowledge/blob/5a0238b2cba175fcacad7afb2c8c8d94801eca8b/docs/src/app/docs/layout.tsx) 使用 **Fumadocs / Next.js**。它的分组导航、正文层次、目录和轻量操作适合借鉴到 AgentWiki 阅读界面，但不是编辑器本身。

OpenKnowledge 产品编辑器则使用 **Tiptap 3 / ProseMirror + CodeMirror 6 + Yjs / Hocuspocus**，文件树使用 `@pierre/trees`。Agent 通过原文写入、编辑器桥接、历史和冲突机制共同工作，不能通过套用官网主题获得这些能力。

## 应借鉴的关键机制

**位置连续性。** OpenKnowledge 通过块类型、正文、块序号和块内选区定位另一编辑模式，无法精确匹配时逐级回退。AgentWiki 已有位置恢复，应强化到“当前段落仍在视野里、选区可恢复”，而非只复用滚动条像素值。[位置解析源码](https://github.com/inkeep/open-knowledge/blob/5a0238b2cba175fcacad7afb2c8c8d94801eca8b/packages/app/src/editor/mode-switch-position-resolver.ts)

**目录操作就在当前节点发生。** 学习其行内重命名、上下文菜单、清楚的拖动落点和紧凑层级。AgentWiki 继续使用 pageId/folderId 与树版本校验；局部过滤必须说明覆盖范围。现有树按层加载，不能只搜索已展开节点却宣称搜索了整个 Space。[FileTree 源码](https://github.com/inkeep/open-knowledge/blob/5a0238b2cba175fcacad7afb2c8c8d94801eca8b/packages/app/src/components/FileTree.tsx)

**批注作为修改输入。** 选中段落后“让 Agent 修改”或“留下批注”，保留原文及前后文；批注锚点失效时显示“原文已变化”，而不是挂到相似但错误的位置。AgentWiki 的批注应受 Space 权限约束。状态建议为待处理→已派发→待验收→已解决，避免把任务送达等同于问题解决。[锚点查找源码](https://github.com/inkeep/open-knowledge/blob/5a0238b2cba175fcacad7afb2c8c8d94801eca8b/packages/app/src/comments/anchor-search.ts)、[批注状态源码](https://github.com/inkeep/open-knowledge/blob/5a0238b2cba175fcacad7afb2c8c8d94801eca8b/packages/app/src/comments/store.ts)

**修改可审阅、可归属、可恢复。** 学习按 Agent、文件和单次修改展示差异。OpenKnowledge 活动面板随 Agent 会话结束消失，Timeline 才是持久历史；AgentWiki 可以利用已有版本和提案数据建立持久记录。[Agent activity](https://openknowledge.ai/docs/features/agent-activity)、[Timeline](https://openknowledge.ai/docs/features/timeline-and-recovery)

## 建议目标交互

一个稳定的文档工作区：左侧空间目录，中央单份文档，右侧按需打开“大纲 / 批注 / Agent / 历史”。顶部保留轻量面包屑、保存状态和主要操作。窄屏时将右侧面板改为抽屉，保留正文空间。

遵守现有项目规范：阅读与编辑互斥，不恢复左右并排的源码/预览；如果可视编辑器试点通过，在同一个编辑画布里切换“可视 / 源码”。目录和面板宽度、展开状态按用户与 Space 隔离保存。保持现有品牌与组件语言，新文案中英双语。

关键任务：

1. 点击目录文档，正文出现，目录自动显示当前文档；返回后恢复阅读位置。
2. 进入编辑，正文不明显位移，光标落在原来阅读的段落；选中后出现就近格式工具。
3. 输入 `/` 插入表格、代码、引用或图片；选择链接时可查找当前 Space 页面。
4. 选中一段后调用 Agent，输入框显示“当前文档 + 已选段落”；全文修改需要明确显示“整篇文档”。
5. 生成过程只更新候选。用户能继续手写；完成后查看差异，接受到草稿或放弃。
6. 草稿基线仍一致时可应用；已变化则重新比对，重叠修改进入冲突处理；正式保存仍执行服务器版本和权限校验。

编辑辅助由用户发起的“应用到我的草稿”和外部 Agent 的 ChangeSet 是两条现有业务路径：可以共用候选 UI，但不能合并身份或绕过角色权限。

## 实施路线与验收

### 第一批：工作区和树，同时解决候选覆盖

三个有清晰边界的任务：

- **阅读/编辑外壳与手工操作。** 共用正文尺寸和标题节奏；阅读/编辑大纲一致；面板响应式；移除多余的编辑框视觉边界。基于现有 CodeMirror 增加选区格式工具、`/` 插入和当前 Space 页面链接选择；第一批插入标准 Markdown，表格行列拖动等完整块操作归入可视编辑试点。
- **目录日常操作。** 菜单文字、就地改名、新建落点、持久化展开/滚动/宽度、当前页定位。过滤先确认服务端检索能力，再定义完整范围。
- **Assist 候选隔离。** 保留现有全文输出契约也能先做：生成内容进入独立候选，真实 diff，明确接受/放弃；基线变化时阻止无条件套用。随后添加本机草稿恢复，不自动把生成中的内容写入正式页面。

验收以实际操作为准：连续切换多篇文档不丢位置；刷新后恢复目录；键盘完成目录菜单；中文输入、图片粘贴正常；选区加粗可撤销，`/` 插入表格与代码块后光标位置正确，页面链接能检索并正确打开；Agent 生成期间手写内容保留；失败/取消不改草稿；恢复旧草稿须比较远端版本；账号切换不泄露前一用户草稿。

### 并行技术试点：真正的可视编辑

只在隔离样例页面试验 Tiptap 或等价方案，保留现有 CodeMirror 源码入口。通过后才决定替换范围。目标是让表格、图片、列表、代码块真正可操作，不把长期目标停在语法高亮和快捷按钮。

往返语料至少覆盖 GFM 表格及转义、中文输入法、嵌套列表、任务勾选、代码围栏、Mermaid、KaTeX、Obsidian callout、WikiLink、块锚点、跨页嵌入、相对附件与未知扩展语法。若出现 YAML frontmatter 或原始 HTML，也必须保留源字节或明确的原文块回退；不把现有未支持的语法误列为已支持能力。

验收要求：只打开不编辑不产生内容变更；局部编辑不重写无关段落；读写切换保持位置；未知语法不丢失；Local Sync 不产生无意义的整篇差异；撤销不撤回别人的修改。CRDT 是否引入单独评估，不随编辑器换库自动决定。

### 第二批：精确的手工 + Agent 协作

扩展 Assist 范围与结果契约；加入选区/章节锚点、批注队列、逐项接受、重叠修改处理、来源和恢复。同步完善 ReviewPage 的真实 diff。只有不重叠且基线可确认的候选才考虑自动合并。

请求至少绑定 `spaceId + pageId + baseVersion`，选区附原文及上下文，不单凭易失效的 offset。执行与应用时均检查当前授权；候选不能因为 UI 里仍显示旧权限就继续发布。

## 路线选择

| 路线 | 收益 | 代价 | 判断 |
| --- | --- | --- | --- |
| 现有编辑器增强 + 可视编辑试点 | 先获得阅读、导航和审阅收益，同时验证富编辑目标 | 有阶段性双实现，但不同时成为双真相 | 推荐 |
| 立即全量切 Tiptap / CRDT | 可视编辑目标更直接 | Markdown 往返、同步、版本、权限、撤销需同时重做和验收 | 不建议作为第一批 |
| Fork 或嵌入整个 OpenKnowledge | 可以较快看到参考 UI | 文件/Git 模型与 AgentWiki Space/数据库模型差异大，许可及发布方式也需核对 | 不作为当前路线 |

## 尚未验证

- OpenKnowledge 桌面输入流畅度、真实多人并发、长文性能。
- AgentWiki 本轮仅查看短文；长文、深目录、移动端、中文输入法仍需后续实施验收。
- Agent 流式覆盖人工修改为已核实调用链上的风险，尚未通过运行任务复现。
- 不将官网视觉质量、源码机制或既有测试数量当作新方案已经验收的证据。

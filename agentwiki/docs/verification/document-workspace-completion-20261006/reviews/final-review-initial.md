These are different geometry rules; sticky-toolbar offset, scroll clamping and mode/layout changes can change the nearest block without any deliberate preview navigation. The controller reproduced the result in the production browser with both an AX selection and a real reverse keyboard selection: toggling preview and returning collapses the selection to the heading at offset 0, with unchanged source. This leaves the approved ordinary roundtrip behavior incomplete.
  - Preserve the original bookmark when only the mode restoration/layout changed the inferred viewport block, while retaining the requirement that an actual deliberate preview move to another paragraph wins. Aligning restore/capture coordinates helps, but a robust decision also needs to account for clamped or delayed layout rather than treating every different viewport offset as user intent.
  - Add a regression that performs the actual mode transition without manually assigning the original paragraph the nearest bounding rectangle. Existing `PageEditor.spec.tsx:1160-1185` forces that assumption and therefore misses this integration failure. Cover a short/clamped document and adjacent blocks under a sticky toolbar, forward/reverse selections, unchanged source and undo depth, plus the existing deliberate-different-block behavior. Repeat the observed production keyboard roundtrip after the fix.

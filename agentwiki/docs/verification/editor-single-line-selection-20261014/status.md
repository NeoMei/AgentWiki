# 编辑状态单行选区不可见修复

- 日期：2026-10-14；基线：`1bbb428e6624719f49452a8cc3924a2d8218711a` / Web 0.12.25。
- 分支：`codex/editor-single-line-selection`。
- 状态：本地修复、真实 Chrome 验证和独立静态审查通过；尚未推送、发布或部署。

## 根因与变更

CodeMirror 在文字下方绘制选区，系统原生选区为透明。原 `.cm-activeLine` 使用不透明 `#fafafa`，遮住 selection.head 所在行的选区，因此同行全不可见，跨行末端行不可见。

活动行改用 `rgb(0 0 0 / 2%)`，在白底上保持近似原外观，允许背后的选区透出。未改选区状态、鼠标事件或层级。新增本地真实编辑器样例 `apps/client/e2e/fixtures/editor-selection.html` / `.tsx`，使用生产组件与 CSS、内存内容及可见选区输出，无 API 写入。

## 修复前证据

- 生产页面 `https://agentwiki.quukk.com/pages/6926feff-a584-43cf-ad38-a31e3fff2232/edit`：真实鼠标拖选后，DOM Selection 为“均为待填写占位符，”，选区矩形宽 144px，背景 `rgb(215,212,240)`；活动行 `rgb(250,250,250)`，屏幕无选区高亮。未修改或保存正文，已返回阅读。
- 本地相同 CSS：拖选范围 4–14、10 字“请在这一行拖动选择中”，可见输出正确但高亮不可见。`local-before.jpg` 为 RED 证据。

# 目录切换反复加载修复

## 原案与原因

在 v0.12.36 生产项目管理空间的原目录中复现。点击另一文件夹的文档发起 12 个目录相关请求，根目录被读取两次，其中一个分支请求被取消；串行请求耗时约 1.35 秒。点击同一文件夹内的另一文档也发起 11 个目录请求。切换后的实际 DOM 曾只剩“加载中…”。

`SpaceWorkspace` 在新文档尚未返回时将目标文件夹临时置空；`useSpaceDirectory` 把目标变化当成完整刷新，清空所有层级，再串行读取根、祖先和所有已展开分支。全部请求结束后才显示目录。

## 实现

- 将用户/空间/显式刷新失效与文档定位分开。已加载目标直接复用目录；未加载目标只补必要祖先与缺失层级，保留已有节点。
- 定位切换只取消旧定位请求，保留无关分支请求；合并并发成功结果。新目录版本触发完整刷新，旧响应不跨用户/空间回填。
- 页面加载中的空身份与 401/403 拒绝访问分开处理，拒绝后清除目录。成功恢复分支只清其旧错误。
- 页面创建、保存、删除等已知变更主动更新目录，保留标题及 `updatedAt` 乐观锁的一致性。晚到的同空间成功回执可刷新目录，但不改变当前文章或跳转；跨身份回执不更新当前目录。
- 将工作区 Scope 组件独立为按需加载模块，避免新增状态逻辑扩大首页启动包；初始 JavaScript 从 549905 降至 548340 bytes，保持原 550000 bytes 预算。

## 浏览器验收

真实 `SpaceWorkspace`、`PagePreview`、`SpaceView` 组件，合成只读数据，目录响应延迟 250 ms、文章响应延迟 600 ms。通过 Chrome CUA 实际点击“合成周报二”（同目录）、“合成任务安排”（跨已加载目录）。

- 文档加载期间，5 个目录节点始终存在，无目录 loading 占位。
- 两次切换后目录请求总数仍为 7；文档请求从 1 增至 3。新增目录请求为 0。
- 这是本地组件验收，不是修复后的生产回验。
- 回执：`browser.json`、`browser.png`；可复现页面：`apps/client/e2e/fixtures/directory-navigation.html`。

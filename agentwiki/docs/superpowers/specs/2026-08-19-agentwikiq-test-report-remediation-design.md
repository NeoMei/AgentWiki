# AgentWikiQ 测试报告修复设计

## 目标

逐条关闭 `测试报告/AgentWikiQ/问题清单.md` 中的 18 条反馈，并把共同根因收敛为可复用、可自动回归的产品能力。修复后，中英文界面、来源导入、页面编辑、权限与审核发布流程应保持一致，不再依赖刷新、滚动查错或识别数据库原始错误。

## 范围与约束

- 修改范围限定为 `agentwiki/` 产品代码、测试和使用指南。
- 保留现有 React/Vite、NestJS、Prisma/PostgreSQL 与 Tailwind 技术栈，不引入第二套 UI 组件系统。
- 所有新增用户可见文案同时支持简体中文与英文，并使用现有语言上下文。
- 保持 Source → Run → ChangeSet → Page 的知识发布链路，不绕过审核与权限模型。
- Agent 仍不得获得 `review:decide`；本次只修复 human Space `admin` 的内容管理权限。
- URL 导入继续执行 SSRF 防护；每次重定向都必须重新校验协议、凭据、DNS 与私网地址。
- Obsidian 社区插件上架申请已经提交且正在审核。本次不重复提交官方上架申请，只把指南改为真实状态，并保留 GitHub Release 手动安装入口。
- 不发布 npm、不推送或合并、不应用生产数据库迁移、不部署生产。
- 不覆盖当前工作区已有的 CodeGraph、自动图谱或其他未提交改动。

## 方案选择

采用“共享根因分组修复”：把 18 条反馈归并为账号与错误体验、指南与 Obsidian、来源导入、权限与编辑器、审核发布五个边界清楚的修复单元。每个单元独立完成失败测试、最小修复和局部回归，再运行全量门禁。

未采用以下方案：

- 逐条打 18 个互不关联的补丁：会重复实现错误提示、状态刷新和权限判断，并留下新的不一致。
- 只改前端提示：无法解决 URL 重定向、软删除唯一键冲突、权限和发布状态等服务端根因。

## 一、账号识别与本地化错误

### 反馈覆盖

- #1 管理员重置密码后用户无法登录
- #2 登录错误提示为英文
- #9 中文审核页仍显示英文错误
- #18 发布失败后必须滚到页面顶部查看错误

### 根因

#1 的截图中，被重置账号与尝试登录账号的邮箱不同，而重置结果弹窗只突出重名用户的名称和密码，容易把临时密码用于另一个账号。当前密码生成、bcrypt 哈希和强制修改密码链路本身保留，但缺少真实哈希校验回归。

客户端目前直接显示 `response.data.message`，因此服务端英文信息和 Prisma 错误会穿透中文界面。审核页错误只显示在页面顶部，长变更集中的用户看不到即时反馈。

### 设计

1. 密码重置确认和结果区域同时显示完整姓名、邮箱与临时密码。
2. 提供“复制登录信息”动作，复制明确标注的邮箱和临时密码，保留单独复制密码动作。
3. 增加共享 API 错误翻译函数，以稳定的业务 `code` 和 HTTP 状态为主，英文 `message` 仅作为英文界面的后备信息。
4. 登录页至少覆盖无效凭据、请求过多、网络失败和通用失败；审核页覆盖状态已变化、权限不足、发布冲突与通用失败。
5. 审核操作错误使用固定在视口右上角的可关闭通知，同时保留无障碍 `role="alert"`；通知不会要求用户滚动。
6. 新增服务测试，用真实 `AuthService.hashPassword`/`validatePassword` 证明返回的临时密码与持久化哈希匹配。

## 二、接入指南与 Obsidian 安装状态

### 反馈覆盖

- #3 使用指南的一键接入指令页面与产品不一致
- #4 统一网关接入指令介绍与产品不一致
- #5 Obsidian 社区市场搜索不到 AgentWiki Sync

### 根因

使用指南仍引用旧版“一键接入”静态截图，而当前产品已经统一为 Agent 详情页中的“AgentWiki 统一网关”卡片。Obsidian 指南把尚未获批的社区市场入口写成了当前可用的推荐安装方式。

### 设计

1. 删除步骤 4 对旧截图和旧凭据界面的依赖。
2. 新增无密钥、无一次性代码的指南预览组件，使用当前统一网关卡片的结构与同一组翻译文案：包名和版本、支持客户端、自动发布复选框、有效期、指令区域、复制与重新生成动作、普通 API Credential 说明。
3. 指南明确导航路径为“智能体 → 目标 Agent → 访问权限 → AgentWiki 统一网关”。
4. Obsidian 页面显示“社区市场审核中”，不再让用户搜索一个尚未进入索引的插件。
5. 当前可用安装方式改为 GitHub Latest Release，列出 `main.js`、`manifest.json`、`styles.css` 与 `.obsidian/plugins/agentwiki-sync/` 目标目录；社区入口保留为审核通过后的未来入口，不标记为可安装。

## 三、来源上传、中文文件名与 URL 导入

### 反馈覆盖

- #6 选择文件后没有明确上传动作
- #7 Markdown 中文文件名乱码且无法完成审核
- #8 URL 来源无法识别
- #17 已批准文档发布时错误提示重复

### 根因

文件来源仍使用浏览器原生文件输入，选中文件后需要回到通用“保存来源”动作，缺少明确状态和动作名称。Multipart 的 `originalname` 可能把 UTF-8 文件名按 Latin-1 解码，形成 mojibake。

URL 抓取禁止所有重定向并把 HTML 原样当 Markdown，常见网站的 301/302 和 HTML 外壳会造成失败或不可读内容。发布时只查找 `deletedAt: null` 的同源页面；同源页面被软删除后仍占用 `(spaceId, sourceId, sourcePath)` 唯一键，新候选项却尝试创建新行，最终暴露 Prisma P2002。

### 设计

1. 文件来源使用明确的“选择文件”控件、已选文件名和“上传文件”主按钮；未选文件时按钮禁用。
2. 选择文件时自动把来源名称填为规范化文件名，用户仍可修改显示名称。
3. 服务端新增保守的 multipart 文件名规范化：仅在 Latin-1 → UTF-8 转换产生有效、无替换字符且明显改善 mojibake 时采用转换结果；否则保留原名。内容仍按 UTF-8 读取，非法 UTF-8 返回本地化的可操作错误，不静默写入乱码。
4. URL 获取实现最多五跳的受控重定向。每一跳都调用同一 URL 安全校验，不允许私网、内嵌凭据或非 HTTP(S) 协议。
5. 仅接收有界文本响应；`text/html` 提取标题、正文可见文本、段落、标题、列表和链接，移除脚本、样式与标签噪音；其他文本类型按文本处理，二进制类型返回明确错误。
6. Run 详情保留最终 URL、内容类型与重定向次数，失败时展示可本地化的阶段错误。
7. 发布 `create_page` 候选项前按同一来源和路径查找软删除页面。若存在，则在同一事务中写入历史版本、恢复该页面并更新来源、内容、同步路径、审计字段和搜索索引；若存在活跃页面，则返回稳定的业务冲突而不是数据库错误。
8. 恢复同源页面沿用原 Page identity，避免重复页面并保持外部链接与历史版本连续。

## 四、Space 管理权限与页面编辑体验

### 反馈覆盖

- #10 编辑者能删除页面而管理员不能
- #11 智能体生成内容在编辑器中不自动换行
- #12 重新打开编辑辅助会恢复历史对话内容并覆盖文档
- #13 历史版本无法预览

### 根因

产品文案定义 Space `admin` 可管理成员和内容，但多个内容写入控制器只允许 `owner`/`editor`。CodeMirror 未启用 `EditorView.lineWrapping`。编辑辅助面板挂载时会自动应用接口返回的所有历史已完成任务，因为本地 `appliedRef` 每次挂载都为空。版本历史只有标题、作者、时间和恢复动作。

### 设计

1. human Space 内容写入角色统一为 `owner`、`admin`、`editor`，覆盖页面创建、更新、删除、恢复、排序、来源、Run、搜索写入和编辑辅助。
2. 审核决定权限保持 owner-only；Agent Grant 仍只使用 viewer/editor，不因本次调整获得 admin 或审核能力。
3. Markdown 编辑器加入 CodeMirror 官方换行扩展，并保持预览模式和现有 Obsidian 式单工作区不变。
4. 编辑辅助只自动应用“面板本次挂载后由用户新提交”的任务。初次加载的历史任务只展示；轮询到当前会话任务完成时才应用一次。
5. POST 创建辅助任务返回的 task id 进入当前会话允许应用集合；重新打开面板时集合为空，因此历史结果不会覆盖已保存页面。
6. 版本历史卡片增加“预览”动作，使用现有 `Markdown` 渲染器在可关闭的展开区域或对话层中显示该版本标题和正文。恢复动作保持独立并继续二次确认。

## 五、审核角标、排序、状态同步与反馈

### 反馈覆盖

- #14 运行后必须刷新才出现待审核角标
- #15 待审核内容排在列表底部
- #16 候选项和变更集按钮没有可见反应
- #18 失败信息不可见

### 根因

Navbar 只在路由路径变化时获取完整审核列表。Review Service 按创建时间升序返回所有状态，导致旧历史记录压在待审核项之前。审核页面虽然有局部刷新代码，但没有统一的成功/失败通知，也没有在所有操作后刷新摘要与详情；无效状态和权限错误仍以页面顶部英文文本呈现。

### 设计

1. 新增轻量待审核计数接口，只返回当前 principal 可见 Space 中 `pending_review` 的数量。
2. Navbar 首次加载、窗口重新获得焦点、页面可见性恢复及每五秒轮询计数；卸载时清理计时器，失败时保留上一次可信计数而不是闪回零。
3. Review 列表使用稳定优先级：`pending_review`、`approved`、`published`、`rejected`、`reverted`；同一状态内按最新创建时间优先。
4. 展开变更集始终获取最新详情。每次候选项决定或变更集动作成功后，同时刷新该详情和列表摘要；角标通过共享刷新事件立即更新，并由轮询兜底。
5. “仅批准”在仍有 pending 候选项时禁用，并显示需要先逐项处理的说明；“通过并发布”保留接受剩余候选项的一步式语义。
6. 状态已被其他操作改变时，客户端显示本地化通知并立即重载详情，不继续展示过期按钮。
7. 所有可操作按钮在请求期间显示禁用/进行中状态；成功和失败都给出可见通知，避免用户重复点击猜测结果。

- `apps/client/src/features/source/SourcesPage.tsx`：明确的文件选择、上传状态和来源错误。

- `apps/client/src/features/page/AgentAssistPanel.tsx`：区分历史任务与当前会话任务。
- `apps/client/src/features/page/PageVersionHistory.tsx`：版本预览状态和渲染。

## 数据流

### 文件来源

用户选择文件 → 客户端规范化显示名称并启用上传 → 服务端校验扩展名、大小、文件名和 UTF-8 → 创建或复用 Source/SourceVersion → Run → ChangeSet → 审核 → 创建或恢复同源 Page。

### URL 来源

用户保存 URL → Run 获取起始 URL → 每跳重新做 SSRF 校验 → 有界获取文本 → HTML 正文提取 → SourceVersion/Artifact/Evidence → ChangeSet → 审核发布。

### 审核状态

Run 或 Agent 产生 ChangeSet → 轻量计数轮询/刷新事件更新 Navbar → Review 按状态优先级展示 → 用户操作前读取最新详情 → 服务端 CAS 状态变更 → 客户端刷新详情、摘要与角标 → 固定通知反馈结果。

## 错误处理

- 客户端优先翻译业务 `code`，不根据数据库字段名生成用户文案。
- 后端捕获预期唯一冲突并转换为业务结果或稳定业务错误；P2002 不应到达 Review UI。
- 文件编码、URL 响应类型、重定向、私网地址、超限和空正文均返回可操作错误。
- 审核 CAS 失败被视为状态已变化，客户端自动刷新并说明原因。
- 通知可关闭，错误通知不会自动过快消失；成功通知可短时自动关闭。

## 测试与验收

每个修复单元先写失败测试并确认失败原因，再写最小实现。最低验收包括：

1. 服务端 Jest：真实临时密码哈希、admin 内容权限、中文文件名规范化、非法 UTF-8、URL 安全重定向、私网重定向拒绝、HTML 正文提取、软删除页面恢复发布、活跃页面冲突、审核计数与排序。
2. 客户端 Vitest：登录错误本地化、重置账号邮箱展示与复制、网关指南当前结构、Obsidian 审核中状态、文件上传按钮、CodeMirror 换行、历史辅助任务不自动应用、新任务只应用一次、版本预览、Navbar 自动计数刷新、Review 优先排序/禁用状态/通知。
3. 回归：现有 Auth、Authorization、Source、Review、PageEditor、AgentAssistPanel、UsageGuide、Navbar 测试全部通过。
4. 全量门禁：`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build`。
5. 浏览器验收：中文与英文各走一遍登录错误、文件来源、版本预览和审核长页面；确认无需刷新角标、无需滚动查看错误、历史助手结果不会覆盖正文。

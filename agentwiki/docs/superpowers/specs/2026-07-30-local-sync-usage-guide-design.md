# 使用指南加入 AgentWiki Local Sync 设计

## 目标

在现有“使用指南”中增加一段面向普通用户的“本地知识同步”说明，让用户理解如何把本地代码仓库或文档目录交给 Codex、Claude Code、OpenCode 等本地 Agent 整理，并在确认后同步到 AgentWiki。

这段说明以实际发布的 npm 包 `@neomei/agentwiki-local-sync@0.1.0` 为准，强调推荐流程和安全边界，不把指南写成命令参考手册。

## 已确认范围

- 内容加入现有 `/guide` 页面，不新增独立指南页。
- 使用 `@neomei/agentwiki-local-sync`，展示当前版本 `0.1.0` 和 npm 页面链接。
- Codex、Claude Code、OpenCode 是当前已验证自动配置的客户端；其他兼容 stdio MCP 的本地 Agent 可按同一协议接入，但指南不把未验证客户端写成已经支持一键安装。
- 主流程由截图和短说明构成，命令仅放在默认收起的“高级命令”区域。
- 截图必须来自真实 AgentWiki 和真实本地 Agent 操作，不使用模拟界面、占位图或拉伸变形的全屏截图。
- 同时支持中文、英文、桌面端和移动端。

## 页面位置与信息层级

在现有“如何接入 Agent”完整流程之后、“权限模型”之前加入“从本地知识创建 Wiki”章节。这样先完成 Agent 身份、凭据和空间授权，再介绍依赖这些权限的本地同步功能，避免用户把“Agent 接入”和“扫描本地目录”误认为同一步。

章节分为三层：

1. 插件概览：说明它解决什么问题、支持哪些 Agent，并提供 npm 链接。
2. 推荐流程：用四个连续步骤说明真实操作。
3. 高级命令和数据边界：默认收起，供需要排障或精细控制的用户查看。

## 插件概览

概览卡片显示：

- 名称：AgentWiki Local Sync；
- npm 包：`@neomei/agentwiki-local-sync`；
- 当前版本：`0.1.0`；
- “在 npm 上查看”外链，并默认在新标签页打开；
- 已验证自动配置 Codex、Claude Code、OpenCode，并说明底层采用标准 stdio MCP，其他兼容客户端可按其自身配置方式接入；
- 一句话用途：在本地分析代码或文档，预览拟同步内容，并在用户明确确认后写入 AgentWiki。

不在概览卡片中直接展示永久 Key，也不推荐用户手工拼装安装命令。

## 推荐流程

### 1. 在 AgentWiki 生成一次性接入指令

用户在 Agent 详情页选择目标本地 Agent，点击“生成本地同步接入指令”。AgentWiki 生成带一次性安装码、固定服务地址和精确插件版本的完整指令。

这里复用真实的接入指令截图，裁剪范围只保留插件卡片、生成结果和复制操作，不展示无关页面区域。

### 2. 把整段指令交给本地 Agent

用户把整段指令作为一条消息交给 Codex、Claude Code 或 OpenCode。由本地 Agent 完成插件安装、MCP 注册以及 `doctor` 连通性检查，并明确告诉用户是否接入成功。其他兼容 stdio MCP 的 Agent 使用同一服务协议，但在没有实际验证前不承诺自动识别和注册。

文案不暗示只有 OpenCode 可用；如截图采用 OpenCode，只标注“以下以 OpenCode 为例”。

### 3. 扫描本地代码或文档并查看预览

用户告诉本地 Agent 要分析的目录和目标 Space。Agent 先在本地检查内容并生成知识库预览，不自动上传。支持范围写为：代码仓库、Markdown、TXT、PDF 和 DOCX 文档目录。

页面展示真实的本地 Agent 预览结果截图，截图中应能看到扫描对象、拟新增或更新内容的摘要，以及等待用户确认的状态；不得展示真实密钥、私人绝对路径或其他敏感信息。

### 4. 明确确认后同步到 AgentWiki

本地 Agent 必须询问用户是否同步。用户明确同意后，Agent 才上传已预览的内容。同步完成后，用户可在 AgentWiki 看到正式页面、来源和活动记录；是否直接发布仍由 Agent 的权限和 Space 审批策略决定。

页面展示真实同步成功结果，至少能证明目标 Space 中出现了对应页面。可复用现有 AgentWiki 发布页面或活动记录截图；如果截图文字与本地同步场景不一致，则重新完成一次真实同步并截图，不能以普通发帖截图冒充本地知识同步。

## 数据和权限边界

在推荐流程下方放置简短提示卡，明确：

- 安装只建立连接，不会自动扫描目录或上传文件；
- 扫描结果会先生成预览，只有用户明确确认后才同步；
- 若扫描需要调用远程模型，本地 Agent 必须单独说明并再次征得同意；
- 本地连接信息和凭据保存在用户本机，凭据不会写入 MCP 配置或页面截图；
- Agent 最终可执行的操作仍受全局凭据、Space 授权和 Space 审批策略共同限制。

不在主流程中展示 `~/.agentwiki` 的具体内部文件结构，以免增加普通用户的认知负担。

## 高级命令

使用可展开的原生详情组件或等价的可访问折叠组件，默认保持收起。展开后只列出命令名称、用途和最短示例：

- `doctor`：检查安装、依赖、身份和权限；
- `inspect`：仅在本地检查目录；
- `scan`：生成本地知识预览，不上传；
- `preview`：再次查看未过期的预览；
- `sync --confirm`：在明确确认后同步预览；
- `upgrade`：把指定连接升级到精确版本；
- `uninstall`：移除本地 Agent 的 MCP 连接。

示例不得包含真实服务密钥、一次性安装码、用户私人路径或内部生产地址。安装仍只推荐使用 AgentWiki 自动生成的整段接入指令，不提供可被误复制的通用永久 Key 模板。

## 截图规范

- 只使用真实系统截图；截图前完成一次真实接入、扫描、预览和同步验证。
- 只截与当前步骤有关的区域，并保留足够上下文证明操作来源。
- 保持原始宽高比，禁止通过固定宽高同时拉伸图片。
- 桌面端可限制最大高度并使用 `object-contain`；移动端按容器宽度等比缩放。
- 截图内容应使用演示项目、演示 Space 和无敏感信息的示例目录。
- 中文与英文共享同一组真实截图时，图片替代文本和图注必须随语言切换；不要求伪造另一语言界面的截图。

## 中英文、可访问性与响应式

- 所有新增标题、说明、按钮、图注、错误和提示同时提供中文与英文。
- npm 链接提供明确名称，并使用 `target="_blank"` 与安全的 `rel` 属性。
- 高级命令折叠状态可通过键盘操作，并向辅助技术暴露展开状态。
- 截图必须有描述实际画面和作用的 `alt`，不能只写“截图”。
- 桌面端步骤可采用左右结构；窄屏自动变为单列，序号、正文、截图和提示保持阅读顺序。
- 长包名、命令和路径允许换行或横向滚动，不得撑破页面。

## 测试与验收

组件测试覆盖：

- 中英文均显示章节标题、包名、版本、npm 链接和支持的 Agent；
- npm 链接地址正确并在新标签页打开；
- 四步推荐流程按正确顺序出现；
- 明确展示“安装不自动扫描”“扫描不自动上传”“同步前需要确认”；
- 高级命令默认收起，展开后包含七类命令；
- 所有新增截图使用预期真实资源与非空替代文本；
- 现有 Agent 接入流程、导航和截图测试不回归。

浏览器验收覆盖：

- 中文与英文各检查一次；
- 桌面宽度和移动宽度各检查一次；
- 高级命令能通过鼠标和键盘展开、收起；
- npm 外链打开正确页面；
- 截图不变形、不空白、不泄露敏感信息；
- 用真实本地 Agent 完成一次“接入 → 扫描 → 预览 → 明确确认 → 同步”，并核对 AgentWiki 页面与活动记录。

## 不做

- 不在指南中内嵌扫描器或文件上传控件。
- 不让网页直接读取用户本地目录。
- 不把命令行参考替代主流程。
- 不创建新的本地同步专属路由。
- 不承诺未经过实际验证的 Agent 客户端或文件格式。
- 不改变插件安装、Space 权限或审批策略的现有实现。

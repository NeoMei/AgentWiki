# AgentWiki 技术债收口与 Sync v3 服务端整合设计

## 目标

把当前 AgentWiki 仓库中仍有价值、尚未进入 `master` 的代码完整纳入主线；删除或归档已被主线取代的本地快照；建立可重复的全量测试、真实 UI 和发布证据，使仓库回到单一可信主线。

## 范围

- 修复当前 `master` 已复现的测试稳定性问题。
- 整合 `codex/referenced-image-sync-v3` 中的协议、数据库迁移、附件版本、引用解析和服务端同步能力。
- 保持 Sync v2 客户端兼容；Sync v3 必须通过能力协商启用，不得强迫现有客户端升级。
- 把 Sync v3 数据库测试纳入全量测试的显式前置条件，缺少隔离数据库时必须失败而不是静默跳过。
- 对发生变更的公共 npm 包执行语义化版本升级、打包验证和发布核验。
- 完成 API、前端、真实浏览器交互、迁移、回归和生产部署验证。
- 对旧工作树、旧 stash 和脏主检出做可恢复归档后收口；不得删除未备份的用户文件。

## 不在本仓库内完成的事项

Obsidian 插件属于独立仓库和发布链路。本次只交付 AgentWiki 服务端及公共协议能力，不把外部插件尚未实现或尚未真实 Vault 验收的状态描述为已完成。若协议发布后插件需要升级，应在其自己的仓库和任务中实施。

## 关键约束

1. `origin/master` 是最终唯一发布分支；所有有价值的本地代码必须在合并后可由远端提交追溯。
2. 数据库测试使用独立 schema/数据库和专用 Redis DB，不连接生产数据。
3. 每个缺陷先以失败测试或已复现失败作为证据，再实施最小修复。
4. 旧脏工作树只有在差异被判定为重复/回退并已建立可恢复快照后才能移除。
5. “测试通过”“代码已推送”“npm 已发布”“生产已部署”“浏览器已验收”分别报告，不能互相替代。

## 验收标准

- Sync v3 分支与当前主线语义合并，无未解决冲突，迁移顺序唯一。
- lint、类型检查、单元/集成测试、数据库测试、构建和安全审计均通过。
- 核心旧版同步路径和新增附件同步路径均有回归证据。
- 真实浏览器完成登录/导航/内容或附件相关交互的可见验证；控制台无值得修复的错误。
- 所有预期发布产物可从 GitHub/npm/生产环境核验，且本地 `master` 与 `origin/master` 一致。
- 未合并分支、无价值 stash、旧工作树和脏主检出均完成分类与可恢复收口。

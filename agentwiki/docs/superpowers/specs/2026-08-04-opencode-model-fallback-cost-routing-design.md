# OpenCode 模型自动降级与成本路由设计

## 目标

为 AgentWiki 服务端内嵌的 OpenCode 辅助写作增加可预测的模型路由：默认优先使用 OpenCode 当前可用的零成本模型，只有免费候选全部失败时才尝试管理员明确授权的付费模型，并在多 Worker 并发下通过共享熔断避免重复撞击故障模型。

该设计只改变服务器端辅助写作的模型选择与执行过程，不改变页面编辑、审核、发布和 Space 授权语义。

## 已确认决策

- 采用“免费模型优先，失败后才降级到付费模型”的成本优先策略。
- 只在技术失败或结果客观无效时切换模型，不使用额外模型调用对内容质量做主观评分。
- 服务器存在某个供应商 Key 不代表允许产生付费调用；付费模型必须出现在管理员显式允许列表中。
- 免费模型从 OpenCode 模型元数据动态发现，并允许管理员通过显式免费列表固定优先级。
- 同一任务最多尝试 3 个免费模型和 1 个付费模型，且受单一任务总超时约束。
- 模型健康状态由 Redis 在 Worker 间共享，连续失败后短期熔断。
- 任务结果记录实际模型、token、费用和脱敏尝试摘要，密钥与原始鉴权错误不得暴露给前端。

## 当前基础

服务端 `OpencodeCliRunner` 已使用项目内固定版本的 OpenCode CLI，通过一次性 `opencode run --format json` 完成页面辅助写作。OpenCode 1.18.12 支持：

- `opencode models --verbose`：输出模型 ID、状态、价格、上下文限制和能力元数据。
- `opencode run --model provider/model --format json`：显式选择模型并输出 JSON 事件。
- `step_finish` 事件：包含 input、output、reasoning、cache token 和实际 `cost`。

当前 Runner 未显式选模、未做候选降级，也未聚合 token/cost 元数据。

## 架构

### `OpencodeModelCatalog`

负责读取、解析和缓存 OpenCode 模型目录，不执行辅助写作。

- 使用与 Runner 相同的受信任 OpenCode 二进制和最小环境变量集合执行 `models --verbose`。
- 解析 OpenCode 连续输出的“模型 ID 行 + JSON 元数据对象”。解析器不得依赖固定缩进或模型数量。
- 只接受 `status=active`、支持文本输入和文本输出的模型。
- 将输入、输出以及 cache read/write 价格都为 0 的模型标记为 `free`；其他已知模型标记为 `paid`。
- 未知、缺失或非有限价格不能被推断为免费。
- 目录默认缓存 10 分钟；刷新失败时可继续使用尚未超过最大陈旧期的最后成功快照，并记录告警。
- 枚举进程使用独立短超时和输出上限，不能占满辅助任务的 180 秒预算。

### `OpencodeModelRouter`

负责为单个辅助任务构建候选链、应用调用上限、跳过熔断模型并汇总结果。

候选顺序：

1. `ASSIST_OPENCODE_FREE_MODELS` 中、且目录元数据确认确实为零成本的活跃文本模型。
2. 动态发现的其他零成本模型，按稳定的模型 ID 顺序追加。
3. `ASSIST_OPENCODE_PAID_MODELS` 中管理员明确授权的模型，保持配置顺序。

规则：

- 同一模型只保留第一次出现的位置。
- 被错误填入免费列表、但元数据不为零成本的模型必须跳过并告警，不能静默当作免费或付费使用。
- 目录暂时失败时优先使用有效的缓存快照；没有可用快照时，未知免费模型不得运行。
- 付费允许列表是明确的费用授权，即使目录暂时不可用也可作为 `paid` 候选，但仍必须遵守付费尝试上限。
- 两类候选都为空时返回可操作的配置错误。
- 发现的免费模型不因为配置了供应商 Key 而改变分类或顺序。

### `OpencodeCliRunner`

Runner 收窄为“一次调用一个指定模型”：

```text
opencode run --model provider/model --format json <prompt>
```

它负责进程生命周期、输出上限、单次超时、事件解析和一次调用的 usage/cost 提取，不负责选择下一个模型。现有最小环境变量白名单继续生效，数据库、Redis、JWT 等服务端秘密不得传给子进程。

### `ModelHealthStore`

通过接口隔离模型健康状态。生产实现使用 Redis，单元测试使用内存 fake。

- Redis key 使用模型 ID 的稳定哈希，避免不受控模型名污染 key。
- 成功调用清除连续失败状态。
- 失败计数、熔断截止时间和探测锁使用 TTL，不能形成永久状态。
- Redis 健康状态失败时路由仍可运行，但退化为单任务内去重并记录告警；不得因此直接跳到付费模型。

## 模型目录与配置

新增配置：

```env
# 留空时完全使用动态发现结果；配置只决定已确认免费模型的优先级。
ASSIST_OPENCODE_FREE_MODELS=opencode/big-pickle

# 只有这里列出的模型才允许产生付费调用；默认必须为空。
ASSIST_OPENCODE_PAID_MODELS=

ASSIST_OPENCODE_MAX_FREE_ATTEMPTS=3
ASSIST_OPENCODE_MAX_PAID_ATTEMPTS=1
ASSIST_OPENCODE_MODEL_CACHE_MS=600000
ASSIST_OPENCODE_MODEL_STALE_MS=3600000
ASSIST_OPENCODE_MODEL_ENUM_TIMEOUT_MS=10000
ASSIST_OPENCODE_ATTEMPT_TIMEOUT_MS=60000
ASSIST_OPENCODE_CIRCUIT_FAILURES=3
ASSIST_OPENCODE_CIRCUIT_WINDOW_MS=300000
ASSIST_OPENCODE_CIRCUIT_OPEN_MS=120000
```

`ASSIST_OPENCODE_TIMEOUT_MS=180000` 的语义调整为整个任务的总模型执行预算。每次调用的实际超时取以下最小值：单次上限、任务剩余时间以及 Worker lease 的安全剩余时间。

所有数字配置必须在启动时校验为有限正整数，并设置合理上限。模型列表按逗号分隔，去除空白、空项和重复项；非法模型 ID 被拒绝并给出明确配置错误。

## 执行流程

1. Router 读取目录快照并构造本次任务候选链。
2. 过滤超出免费/付费尝试上限的候选。
3. 查询 Redis 健康状态，跳过仍在熔断期的模型。
4. 如果所有候选均处于熔断状态，只允许最早恢复的免费模型获取一次分布式半开探测锁；不能因此直接探测付费模型。
5. 为候选计算剩余时间，调用 Runner 一次。
6. 成功且结果有效时清除失败状态，立即返回，不继续消耗其他模型。
7. 可降级失败时写入失败状态和脱敏尝试记录，再选择下一个候选。
8. 全局故障、任务总超时或候选耗尽时停止，并返回汇总错误。

路由不会在同一个模型上做隐藏重试；下一次尝试必须是另一个候选模型。队列层对 Worker 崩溃的租约恢复与模型路由是两个不同层次，不应相互重复计数。

## 成功与失败分类

### 成功条件

一次调用必须同时满足：

- OpenCode 进程正常退出。
- JSON 事件流可以解析。
- 能提取包含 `changes` 的最终响应。
- `changes` 是非空字符串。
- 事件流中不存在更高优先级的模型错误终态。

`summary` 缺失时可以使用固定的本地兜底文案；`changes` 缺失或无效时不能把原始事件文本当作页面内容。

### 可降级错误

- 模型不存在、已下线或当前不可用。
- 限流、供应商过载或模型级网络错误。
- 当前模型或供应商鉴权失败。
- 单次模型调用超时。
- 进程非零退出且错误属于模型调用阶段。
- 输出为空、JSON 事件损坏、没有有效 `changes` 或响应格式无法验证。

### 立即终止的全局错误

- OpenCode 二进制不存在或不可执行。
- OpenCode 配置目录不可访问。
- 任务输入不合法，或生成 prompt 失败。
- 没有目录快照且没有任何明确可执行候选。
- 总时间预算已经耗尽。
- 输出超过安全上限或出现本机资源保护错误。

错误分类基于结构化事件、退出码和有限的稳定错误码/模式完成。无法识别的错误默认按全局错误处理，防止未知故障触发连续付费调用。

## 熔断与并发

- 同一模型在 5 分钟窗口内连续失败 3 次后熔断 2 分钟。
- 明确的限流、模型不存在或模型不可用可以立即进入短期熔断。
- 鉴权失败按模型/供应商候选记录，并熔断，避免错误 Key 在并发任务中反复计费或报错。
- 成功一次立即重置连续失败计数。
- 半开探测通过 Redis 原子 `SET NX PX` 保证同一模型同一时间只有一个 Worker 探测。
- 熔断只影响新的任务选择，不杀死已经运行的 OpenCode 进程。

单任务最多尝试 3 个免费模型和 1 个付费模型。配置可以进一步收紧，但不能在没有明确修改安全上限的代码与测试时无限放大。

## 结果与可观测性

`AssistRunResult` 增加安全元数据：

- `model`：最终成功模型。
- `modelTier`：`free` 或 `paid`。
- `attemptCount`：总尝试次数。
- `usage`：input、output、reasoning、cache read/write token 汇总。
- `cost`：OpenCode `step_finish` 事件报告的实际总费用。
- `attempts`：模型、tier、耗时、成功状态和脱敏错误类别，不包含 stderr 原文、Key 或供应商响应正文。

任务 API 可以返回上述安全摘要，辅助界面至少显示实际模型、尝试次数和总成本。原始事件流继续只用于受限服务端诊断，并受现有长度上限约束。

结构化日志记录：任务 ID、模型、tier、耗时、token、cost、错误类别、熔断变化与目录刷新结果。日志不得记录页面全文、用户 prompt、API Key、认证 header 或未脱敏供应商错误。

第一版不新增成本报表或计费系统；先保证每个任务有可靠的可聚合数据。

## 安全边界

- 只有 `ASSIST_OPENCODE_PAID_MODELS` 构成付费授权，Key 检测、模型目录发现和 OpenCode 默认模型都不能替代该授权。
- 模型 ID 只能作为独立 argv 传给 `spawn`，不能经过 shell 拼接。
- OpenCode 子进程继续使用环境变量白名单。
- 模型目录与执行输出都使用字节上限和超时。
- 前端错误只展示稳定错误码与可操作说明，不展示本机路径、stderr、供应商响应或密钥存在性。
- 免费模型的 `cost=0` 判定必须来自成功解析的有限数字元数据，fail closed。

## 测试设计

### 单元测试

- 解析多个连续的 OpenCode verbose 模型对象、嵌套 JSON 和异常尾部。
- 只发现 active 文本模型；严格识别全维度零成本。
- 显式免费顺序、动态追加、去重、非法免费模型跳过和付费 allowlist。
- 没有目录、陈旧缓存、刷新并发合并与目录超时。
- token/cost 事件聚合、有效结果、空结果、错误事件和损坏 JSON。
- 模型级错误与全局错误分类。
- 免费/付费尝试上限、总时间预算与剩余时间计算。
- 连续失败、直接熔断、成功复位、半开探测锁和 Redis 退化行为。
- 错误与日志脱敏。

### 集成测试

使用可控的假 OpenCode 可执行程序验证完整顺序：

- 第一个免费模型限流，第二个免费模型成功，不调用付费模型。
- 免费模型全部无效，唯一显式付费模型成功。
- 配置了 Key 但付费 allowlist 为空时绝不调用付费模型。
- 某模型熔断后多个并发任务不会同时探测。
- 单次超时后使用剩余总预算调用下一个模型。
- OpenCode 二进制缺失时立即结束，不遍历所有模型。

### 全量门禁

- Assist 相关服务端测试。
- 服务端、客户端和 local-sync 全量测试。
- TypeScript 类型检查、ESLint、生产构建与 `git diff --check`。

### 真实系统验收

1. 使用项目内固定版本的真实 OpenCode CLI 执行 `models --verbose`，确认至少发现一个元数据为零成本的活跃文本模型。
2. 创建一次性 Space/Page，提交真实辅助写作任务。
3. 确认任务成功，并记录实际模型、tier、token、cost 和尝试次数。
4. 使用受控的无效第一候选验证真实降级顺序，同时保证付费 allowlist 为空时不产生付费调用。
5. 生产部署前备份 PostgreSQL；部署后检查 API、Worker、Frontend systemd 和 `/api/health`。
6. 在生产创建一次性测试数据完成同样的辅助任务 smoke，随后清理测试数据并复核日志无敏感内容。

## 部署与回滚

1. 备份生产 PostgreSQL，并保存当前环境文件的权限受控副本。
2. 默认保持 `ASSIST_OPENCODE_PAID_MODELS` 为空，只启用动态免费模型。
3. 部署并重启 Worker；API 与前端只在其代码确有变化时重启。
4. 验证模型目录刷新、免费模型辅助任务和成本元数据。
5. 如需启用付费降级，管理员单独设置允许列表并再次执行受控 smoke。
6. 回滚时恢复旧代码和环境配置；新增 result JSON 字段保持向后兼容，不要求破坏性数据迁移。

## 完成标准

- 默认零配置能够动态发现并优先使用真实免费模型。
- 免费候选成功时不调用任何付费模型。
- 只有显式 allowlist 中的模型可能产生付费调用。
- 模型级故障会按顺序降级；全局故障不会触发无意义遍历。
- 多 Worker 对故障模型共享熔断与单一半开探测。
- 每个任务受 3 次免费、1 次付费和 180 秒总预算约束。
- 成功任务记录准确的最终模型、token、cost 和脱敏尝试摘要。
- 真实 OpenCode、本地全量门禁与生产辅助写作 smoke 均通过。

## 不做

- 不增加内容质量评分模型或模型自评重试。
- 不根据检测到的 API Key 自动授权付费模型。
- 不引入 LiteLLM、OpenRouter 路由服务或新的常驻 OpenCode Server。
- 不在本版实现成本报表、用户额度、套餐计费或按 Space 分摊。
- 不允许普通用户从前端修改全服模型列表或服务器 Key。

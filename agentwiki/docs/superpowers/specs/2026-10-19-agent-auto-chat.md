# 内嵌 Agent 自动聊天与文档操作

用户已明确要求移除问答、修改候选、直接修改等模式选择，由提示词决定响应行为。本次沿用目录访问修复分支，基线为 `519a7100`；暂不部署生产。

## 行为

- 一个输入框发送自然语言，普通提问、总结、解释及“只给草稿，不保存”直接在聊天中回答。
- 明确要求修改当前文章时保存修改；明确要求新建文档时在当前目录创建。目标不明或要求修改范围外文章时先在聊天中澄清。
- 已登录用户的实时权限决定可用操作。只读用户仍可问答和获得聊天中的草稿，不允许通过模型结果获得写权限。
- 保存成功后显示应用生成的结果回执和文档链接；不能把模型自称“已保存”视为成功。
- 保留历史 question/proposal 记录和旧候选的查看能力，新请求统一使用 auto。

## 实现边界

1. 请求增加 `mode: auto`。应用层提供 `{update, create}` 能力，不能信任客户端声明的权限。
2. 模型先只依据最新用户意图及可用操作选择 answer/update/create，判定阶段没有正文、引用、目录工具或历史内容。第二阶段使用授权来源生成内容，不能把 answer 升级为写操作；写操作可降级为聊天澄清。
3. 严格结构化输出：answer 只有 summary；update 为 summary/changes；create 为 summary/title/changes。模型不能指定 pageId、folderId、Space 或文件路径。
4. 服务端在实时授权、任务租约、取消状态、页面版本和目录有效性检查后，将页面变更与任务完成状态置于同一事务。重试或重复轮询不能重复创建、保存。
5. 复用页面版本、目录路径、空间修订和内容索引机制。阅读页及目录在真实回执后刷新；编辑页若在执行期间产生新草稿，保留该草稿并提示远端已变更，不覆盖新输入。
6. 原有目录只读 MCP 维持只读；写入由应用层完成。模型调用共享总截止时间和取消信号。

## 实施与验收

- 后端子任务：auto 合约、原子文档写入、实时权限、CAS、幂等和取消回归。
- 运行器子任务：无来源的意图判定、严格输出校验、锁定动作、预算与取消回归。
- 前端子任务：移除模式选择、统一发送、真实保存回执、草稿保护和目录刷新。
- 集成验收：真实 API/Worker/数据库/模型执行问答、更新、新建、禁止保存、引述写入指令及恶意来源指令六类场景；页面内容、版本、目录和任务回执分别回读。
- 最终检查：相关与全量回归、类型/lint、生产构建、真实浏览器、独立整分支审查。首屏 550000 字节预算不放宽。

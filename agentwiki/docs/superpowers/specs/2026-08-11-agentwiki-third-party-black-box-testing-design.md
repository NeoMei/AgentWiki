# AgentWiki 0.3.1 第三方生产环境黑盒验收测试 Spec

- 文档版本：1.0
- 编制日期：2026-08-11
- 被测系统：AgentWiki 0.3.1
- 生产地址：<https://agentwiki.quukk.com>
- 接入包：`@neomei/agentwiki-local-sync@0.3.1`
- 测试类型：第三方、生产环境、受控黑盒验收
- 适用对象：独立测试机构、外部 QA 团队、上线验收人员

## 1. 目的

本 Spec 用于验证 AgentWiki 的核心业务闭环、角色权限、知识发布、本地知识同步、Agent 自助接入和平台管理能力。测试人员只使用公开网页和公开 npm 命令，不需要源码、数据库、服务器或内部 API 权限。

验收重点不是单个页面是否可打开，而是以下完整闭环是否可靠：

1. 人类用户能够建立并维护 Space 知识库。
2. 多个用户能够按角色协作且不能越权。
3. Agent 只能在显式授权范围内工作。
4. Agent 或 Source 产生的内容必须遵守审核策略后才能成为正式知识。
5. 本地知识能够预览、确认、同步、拉取和处理冲突，且不泄露凭据。
6. 管理员只能管理测试账号，并且关键身份保护有效。

## 2. 测试范围

### 2.1 纳入范围

- 产品首页、使用指南和 Agent 接入说明
- 注册、登录、退出、密码变更和认证失效
- Dashboard 与 Space 创建、设置、成员和角色
- 页面树、Markdown 编辑、预览、排序、版本历史和恢复
- 搜索、知识图谱和页面关系
- Agent 接入、状态、凭据、Space Grant 和撤权
- Source、运行记录、ChangeSet、Diff、证据、批准、拒绝和发布
- Codex、Claude Code、OpenCode 自助接入兼容性
- 本地知识扫描、预览、同步、Pull/Push、冲突和恢复
- 平台管理员统计、用户搜索、密码重置、锁定、解锁和软删除
- 中英文、桌面端、390px 移动端和关键异常交互
- 权限隔离、重复操作、失效会话、输入安全和敏感信息保护
- 测试数据清理与清理后的权限复测

### 2.2 不纳入范围

- 压力、容量、DoS、暴力破解或大规模并发测试
- 未经书面批准的漏洞利用、端口扫描或服务器探测
- 修改、锁定、重置或删除任何真实用户
- 操作不带测试前缀的 Space、页面、Agent、Source 或 ChangeSet
- 使用真实密钥、真实客户资料、商业机密或个人敏感信息
- 直接访问数据库、Redis、服务器文件系统或内部管理接口
- 第三方模型本身的回答质量、价格或可用性承诺

## 3. 生产测试安全规则

1. 所有测试实体必须使用前缀：`3PT-YYYYMMDD-测试员缩写-序号`。
2. 测试邮箱应使用测试方控制的独立邮箱，不复用个人或生产账号。
3. 密码、Token、Cookie、API Key、Device Code 和安装凭据不得写入报告或截图。
4. 测试截图必须遮挡所有认证信息和个人信息。
5. 只允许测试方创建的用户和专门分配的测试管理员互相操作。
6. 本地知识同步必须使用隔离 HOME/配置目录，不得修改测试人员日常 Codex、Claude Code 或 OpenCode 配置。
7. 测试本地目录只能包含合成数据，不得包含真实代码库或真实凭据。
8. 任何删除动作执行前，必须再次确认目标名称以 `3PT-` 开头。
9. 出现第 14 节任一停止条件时，立即终止测试并通知系统负责人。

## 4. 测试角色与资源

### 4.1 账号角色

| 角色 | 账号要求 | 主要用途 |
|---|---|---|
| 用户 A | 普通 human 用户 | Space Owner，执行主要业务旅程 |
| 用户 B | 普通 human 用户 | Admin/Editor/Viewer 角色切换与协作 |
| 用户 C | 普通 human 用户 | 非成员，验证数据隔离和直接 URL 越权 |
| 管理员 D | 专用 `super_admin` 测试账号 | 只管理 A/B/C 和测试资源 |
| 测试 Agent | 由用户 A 通过 Device Auth 新建 | Agent 授权、审核、撤权和同步 |

账号凭据由测试负责人通过安全渠道单独发放，不写入本 Spec。

### 4.2 客户端与浏览器

- Chrome 当前稳定版：执行全部网页用例。
- Chrome 390px 视口：执行移动端关键用例。
- Codex、Claude Code、OpenCode：使用三个完全隔离的 HOME 或配置目录。
- Node.js：使用 npm 包声明支持的版本。
- 本地测试目录示例：`3PT-20260811-QA01-local-01/`。

### 4.3 合成测试内容

创建三个 Markdown/TXT 文件：

- `overview.md`：产品概述和链接到 `setup.md`。
- `setup.md`：安装步骤，后续用于修改和冲突测试。
- `obsolete.md`：用于删除预览和归档测试。

内容中加入唯一标识 `3PT-KNOWLEDGE-YYYYMMDD-序号`，便于搜索和清理。敏感信息测试只能使用明显标注为假的字符串，例如 `FAKE_TOKEN_3PT_DO_NOT_USE`。

## 5. 进入与退出条件

### 5.1 进入条件

- 生产首页可通过 HTTPS 访问。
- 测试负责人确认当前允许进行受控写测试。
- A/B/C/D 四个测试账号可用。
- 三个隔离客户端环境已准备完成。
- 测试方已建立缺陷登记和截图存储目录。
- 生产环境没有正在处理的严重事故。

### 5.2 退出条件

- 所有 P0 用例执行完毕。
- P0 通过率为 100%。
- P1 通过率不低于 95%。
- 不存在未关闭的 S0、S1 或 S2 缺陷。
- 没有越权、数据泄露、静默覆盖或不可清理数据。
- 所有测试资源已清理，遗留数据清单为空。
- 清理后的首页、登录和核心只读功能仍正常。

## 6. 结果与证据规范

每个用例记录：

- 用例编号、优先级和执行人
- 开始时间、结束时间和客户端
- 使用角色和测试实体名称
- 实际步骤与实际结果
- `通过 / 失败 / 阻塞 / 不适用`
- 截图、录屏或日志文件名
- 缺陷编号和复现概率
- 清理动作与清理结果

P0 用例必须至少保存关键操作前、操作后和最终结果三类证据。不得保存认证凭据、Device Code、Token、Cookie 或密码。

## 7. 环境与公开入口冒烟

### ENV-001 生产首页与 HTTPS（P0）

**步骤**

1. 无登录状态访问生产首页。
2. 检查浏览器地址栏、证书状态和页面主内容。
3. 刷新页面并打开使用指南和 Agent 接入页。

**预期**

- 使用 HTTPS，无证书警告或混合内容阻断。
- 首页、指南和接入页可正常显示。
- 页面不暴露服务器路径、内部堆栈或环境变量。

### ENV-002 健康接口（P0）

**步骤**：浏览器访问 `https://agentwiki.quukk.com/api/health`。

**预期**：HTTP 200；整体状态为 `ok`；database、redis、auditPersistence 均为 `ok`。

### ENV-003 旧接入接口退役（P1）

**步骤**：访问 `https://agentwiki.quukk.com/api/onboard.json`。

**预期**：实际 HTTP 状态为 410，正文只给出 0.3.1 替代命令，不提供旧双 MCP 安装方式。

## 8. 账号与认证

### AUTH-001 注册和首次登录（P0）

**步骤**

1. 分别注册用户 A、B、C。
2. 使用每个账号登录并进入 Dashboard。
3. 刷新页面。

**预期**

- 合法注册成功，重复邮箱被明确拒绝。
- 登录后显示正确用户身份。
- 刷新后仍保持合法登录状态，不出现空白页或循环跳转。

### AUTH-002 错误凭据与错误提示（P0）

**步骤**：使用错误密码、空密码和不足最小长度的密码尝试登录或注册。

**预期**：操作被拒绝；提示可理解；不区分“账号存在”和“密码错误”到足以帮助枚举；不显示堆栈或数据库错误。

### AUTH-003 退出和受保护页面（P0）

**步骤**

1. 用户 A 登录后记录一个测试 Space URL。
2. 退出登录。
3. 使用地址栏、浏览器后退和刷新重新访问该 URL。

**预期**：退出后不能继续读取受保护数据；被引导到安全登录入口；后退不会恢复可交互的敏感页面。

### AUTH-004 管理员重置密码后的强制变更（P0）

**步骤**

1. 管理员 D 重置用户 B 的密码。
2. 用户 B 使用旧密码登录。
3. 用户 B 使用临时密码登录。
4. 设置符合规则的新密码并重新登录。

**预期**

- 旧密码立即失效。
- 临时密码只允许进入强制改密流程。
- 两次新密码不一致时不能提交。
- 改密成功后临时密码失效，新密码可用。

### AUTH-005 锁定和解锁（P0）

**步骤**

1. 用户 B 保持一个已登录浏览器会话。
2. 管理员 D 锁定用户 B。
3. 用户 B 刷新并尝试读写测试 Space。
4. 管理员 D 解锁用户 B，用户 B 重新登录。

**预期**

- 锁定后已有会话和新登录均不能继续访问。
- 解锁不会自动恢复旧会话；重新登录后正常。

### AUTH-006 软删除（P0）

**步骤**：管理员 D 软删除一个仅用于本用例的测试账号，然后尝试使用该账号登录和访问旧 URL。

**预期**：账号不可登录，旧会话不可继续访问；管理员列表显示删除状态；真实用户不受影响。

## 9. Space、成员与权限隔离

### SPACE-001 创建和设置 Space（P0）

**步骤**

1. 用户 A 创建 `3PT-*` Space。
2. 设置名称、描述和 `always-review` 审核策略。
3. 刷新并重新进入 Space。

**预期**：Space 可见且设置持久化；用户 A 为 Owner；导航进入正确 Space。

### SPACE-002 添加用户成员（P0）

**步骤**

1. 用户 A 通过邮箱添加用户 B 为 Editor。
2. 用户 B 登录并访问 Space。
3. 用户 B 创建并编辑测试页面。

**预期**：成员添加成功且不产生重复成员；Editor 可读写页面，但不能获得 Owner 专属能力。

### SPACE-003 Viewer 只读（P0）

**步骤**：将用户 B 调整为 Viewer，刷新其浏览器，然后尝试创建、编辑、重排和修改设置。

**预期**：Viewer 可读取授权内容，但所有写操作被隐藏或明确拒绝；直接访问编辑 URL也不能写入。

### SPACE-004 非成员隔离（P0）

**步骤**

1. 用户 C 登录。
2. 通过 Dashboard、搜索、地址栏直接 URL 和浏览器历史尝试访问测试 Space、页面、图谱、成员、Source 和 Run。

**预期**：用户 C 看不到测试 Space；直接 URL 不返回内容；搜索和图谱不泄露标题、摘要或数量。

### SPACE-005 移除成员后立即失权（P0）

**步骤**

1. 用户 B 以 Editor 打开页面编辑器但不保存。
2. 用户 A 移除用户 B。
3. 用户 B 尝试保存、刷新和访问其他 Space 页面。

**预期**：保存被拒绝；刷新后不能读取；不会因编辑器已打开而绕过撤权。

### SPACE-006 Agent 成员与 Grant（P0）

**步骤**：用户 A 将测试 Agent 添加到 Space，选择 Agent 角色和权限范围，然后在 Agent 详情页确认 Grant。

**预期**：Agent 只获得选择的 Space 和权限；重复添加不会生成重复 Grant；其他 Space 不可见。

## 10. 页面、版本与知识组织

### PAGE-001 创建父子页面（P0）

**步骤**：创建父页面、两个子页面和一个同级页面，并刷新 Space。

**预期**：层级和标题正确持久化；页面树可以展开、收起和定位；不存在重复页面。

### PAGE-002 Markdown 编辑与预览（P0）

**步骤**

1. 编辑标题、段落、列表、代码块、表格和内部页面链接。
2. 保存并进入预览。
3. 刷新并重新打开。

**预期**：Markdown 正确渲染；代码块和表格可读；内部链接指向正确页面；保存结果持久化。

### PAGE-003 并发更新保护（P0）

**步骤**

1. 用户 A、B 同时打开同一测试页面。
2. A 保存修改。
3. B 在旧页面上保存不同修改。

**预期**：系统不能静默覆盖 A 的新内容；B 获得冲突或刷新提示；最终内容来源明确。

### PAGE-004 页面排序和层级调整（P1）

**步骤**：调整同级页面顺序，并将测试子页面移动到另一测试父页面下。

**预期**：刷新后顺序和层级保持；移动不造成丢失、复制或循环层级。

### PAGE-005 版本历史与恢复（P0）

**步骤**

1. 连续保存三个明显不同的版本。
2. 打开版本历史并查看旧版本。
3. 恢复第一个版本。

**预期**：历史顺序、时间和内容正确；恢复后正文等于目标旧版本；恢复动作本身留下可追溯的新版本。

### PAGE-006 输入安全（P0）

**步骤**：在测试页面输入 `<script>alert('3PT')</script>`、`javascript:` 链接和普通 HTML 文本，保存并查看预览。

**预期**：不执行脚本，不出现弹窗，不跳转到危险协议；文本被转义、清理或安全拒绝。

## 11. 搜索、图谱与页面关系

### SEARCH-001 唯一内容搜索（P0）

**步骤**：保存唯一标识，等待正常索引时间后使用全局搜索。

**预期**：授权用户能搜索到正确 Space 和页面；结果链接可打开；用户 C 搜索不到该标识。

### SEARCH-002 更新和删除后的搜索（P1）

**步骤**：修改唯一标识并删除旧测试页面，然后再次搜索旧值和新值。

**预期**：新内容最终可检索；已删除内容不作为可访问结果残留；旧结果链接不能泄露正文。

### GRAPH-001 知识图谱隔离（P0）

**步骤**：在测试 Space 打开知识图谱，检查测试页面和关系；再以用户 C 尝试访问同一图谱 URL。

**预期**：成员看到的节点和关系与测试数据一致；非成员不能看到节点名称、关系或数量。

## 12. Source、运行记录和审核发布

### SOURCE-001 文本 Source 和 Run（P0）

**步骤**

1. 用户 A 在测试 Space 创建文本 Source。
2. 输入带唯一标识的合成 Markdown。
3. 启动处理并查看 Runs。

**预期**：Source 创建成功；Run 状态可追踪；完成、失败或部分完成都有明确结果；不会暴露内部堆栈。

### SOURCE-002 失败与重试可见性（P1）

**步骤**：使用一个明确无效、但不会攻击外部系统的测试 URL Source，观察失败状态和重试展示。

**预期**：失败原因可理解；页面不会无限加载；重复点击不会产生失控的重复 Run。

### REVIEW-001 待审核内容不进入正式知识（P0）

**步骤**：在 `always-review` Space 中完成 Source Run，打开 Review 队列，然后在批准前搜索和访问目标页面。

**预期**：产生待审核 ChangeSet；正式页面在批准前不包含候选变更。

### REVIEW-002 Diff 与证据（P0）

**步骤**：查看 ChangeSet 的新增、修改、删除项、Diff 和证据。

**预期**：变更类型、旧值、新值和来源清晰；证据与测试 Source 对应；不存在其他 Space 数据。

### REVIEW-003 拒绝（P0）

**步骤**：拒绝一个测试 ChangeSet，然后刷新页面、搜索和图谱。

**预期**：ChangeSet 显示拒绝；候选内容不进入正式知识；拒绝原因或状态可追溯。

### REVIEW-004 批准和发布（P0）

**步骤**：重新产生变更并批准。

**预期**：ChangeSet 发布成功；页面、搜索、图谱、版本记录和运行结果保持一致；重复批准不会重复创建内容。

### REVIEW-005 撤权期间发布保护（P0）

**步骤**

1. 让测试 Agent 或用户产生一个待处理 Run/ChangeSet。
2. 在其完成或发布前撤销对应 Grant 或锁定请求用户。
3. 等待任务结束并检查正式知识。

**预期**：撤权后任务不能继续以旧权限发布；正式知识不变化；状态和失败原因可理解。

## 13. Agent 自助接入与本地知识同步

### 13.1 固定接入命令

```bash
npx --yes @neomei/agentwiki-local-sync@0.3.1 onboard --server https://agentwiki.quukk.com/api --protocol ndjson
```

该命令应交给目标 Codex、Claude Code 或 OpenCode Agent 执行，由 Agent 按 NDJSON 协议收集和提交测试人员的选择；不要把它当作普通交互式终端向导。不得改用未固定版本、旧 `connect` 命令或双 MCP 安装方式。

### ONBOARD-001 完整 Device Auth（P0）

**步骤**

1. 在隔离 HOME 中执行固定命令。
2. 打开命令给出的浏览器授权页。
3. 以用户 A 登录并确认显示的客户端和版本。
4. 批准连接。

**预期**：密码不进入终端或 Agent 对话；授权页显示正确客户端和 0.3.1；批准后终端继续；同一授权 Token 不能被重复消费。

### ONBOARD-002 接入计划确认（P0）

**步骤**：填写 Agent 名称、创建或选择测试 Space、选择 `editor` 权限和 `always-review`，检查汇总后确认。

**预期**：确认前不执行安装或同步；汇总与输入一致；服务端计划和本地扫描路径边界清晰。

### ONBOARD-003 单一 MCP 安装（P0）

**步骤**：接入完成后检查目标客户端 MCP 配置和 `doctor` 输出。

**预期**：只有一个名为 `agentwiki` 的本地网关条目；不存在旧 remote/local 双条目；网关验证成功或明确要求重载客户端。

### ONBOARD-004 首次扫描、预览和同步（P0）

**步骤**

1. 选择合成 Markdown/TXT 目录。
2. 执行首次扫描。
3. 检查新增、修改、删除、跳过文件和上传量预览。
4. 在确认前检查远端。
5. 确认同步并在网页查看结果。

**预期**：确认前不上传；预览与文件变化一致；确认后产生可审核结果；纯 Markdown/TXT 不长时间等待 Python/MarkItDown 安装。

### ONBOARD-005 取消和恢复（P0）

**步骤**

1. 在授权后、计划确认前中断一次。
2. 使用输出的 session ID 恢复。
3. 在首次同步确认前再中断并恢复。

**预期**：恢复到正确检查点；不重复创建用户、Agent、Grant、Space 或 MCP 条目；已确认步骤不被错误重放。

### ONBOARD-006 拒绝、过期和重复授权（P1）

**步骤**：分别拒绝一个连接请求、让一个请求自然过期，并尝试重复使用已完成请求。

**预期**：三种状态均有明确终态；不能获得有效安装凭据；不会留下活跃 Agent 或 Grant。

### ONBOARD-007 三客户端兼容性（P0）

**步骤**

- 选择 Codex、Claude Code 或 OpenCode 之一完成 ONBOARD-001 至 ONBOARD-005。
- 另外两种客户端至少完成 Device Auth、计划确认、单一 MCP 安装和 `doctor`。

**预期**：三种客户端均成功；配置写入各自隔离 HOME；互不覆盖或读取其他客户端配置。

### SYNC-001 Push 和远端可见性（P0）

**步骤**：修改 `setup.md`、新增一个文件、删除 `obsolete.md`，执行扫描和预览，再确认 Push。

**预期**：预览分别显示修改、新增和删除；远端结果与确认内容一致；未经确认不应用删除。

### SYNC-002 第二环境 Pull（P0）

**步骤**：在第二个隔离环境接入同一测试 Space 并 Pull。

**预期**：拉取到最新权威 Revision；不拉取其他 Space 数据；本地状态记录正确基线。

### SYNC-003 冲突保护（P0）

**步骤**

1. 两个隔离环境从同一 Revision 开始。
2. 环境一修改并 Push。
3. 环境二对同一内容做不同修改并尝试 Push。

**预期**：环境二不能静默覆盖环境一；提示 Pull/合并/确认；冲突解决后 Revision 连续且来源明确。

### SYNC-004 假凭据保护（P0）

**步骤**：在合成文件中加入 `FAKE_TOKEN_3PT_DO_NOT_USE`，执行扫描和预览。

**预期**：系统将其标记、跳过或脱敏；报告、预览、网页和错误消息不显示完整敏感值；不得使用真实凭据测试。

### SYNC-005 重复同步幂等（P1）

**步骤**：不修改本地文件，连续执行两次扫描/同步。

**预期**：第二次显示无变化或等价结果；不重复创建页面、关系、Revision 或 ChangeSet。

### SYNC-006 卸载和配置恢复（P0）

**步骤**：记录隔离环境接入前配置，完成接入后执行卸载或恢复流程，再比较配置。

**预期**：移除测试 `agentwiki` 条目；恢复接入前配置；不影响其他非测试 MCP；归档和错误信息不包含凭据。

## 14. 平台管理员

### ADMIN-001 访问控制（P0）

**步骤**：用户 A 和管理员 D 分别访问 `/admin`。

**预期**：普通用户不能查看管理员数据；管理员 D 能进入专用页面。

### ADMIN-002 统计和用户搜索（P1）

**步骤**：管理员 D 查看统计，按测试邮箱、名称、状态和角色搜索 A/B/C。

**预期**：测试用户可被准确检索；状态与实际一致；分页和筛选不会展示密码或 Token。

### ADMIN-003 重置、锁定、解锁和删除（P0）

**步骤**：只对测试用户依次执行重置、锁定、解锁和软删除，并完成 AUTH-004 至 AUTH-006 的用户侧复测。

**预期**：每项动作立即生效且有反馈；旧会话和旧密码按规则失效；其他用户不受影响。

### ADMIN-004 管理员保护（P0）

**步骤**：管理员 D 尝试对自己执行锁定、删除或高风险操作。

**预期**：系统阻止管理员自操作；不得尝试操作任何非测试管理员或验证“最后一个真实管理员”场景。

## 15. 跨端、国际化与异常交互

### UX-001 中英文切换（P1）

**步骤**：在首页、Dashboard、Space、页面、Agent、审核和管理员页切换中英文。

**预期**：核心文案同步切换；不出现乱码、缺失键名或布局严重溢出；刷新后语言选择保持。

### UX-002 桌面端和 390px 移动端（P1）

**步骤**：在 390px 视口执行登录、导航、Space 打开、页面阅读、成员查看和审核查看。

**预期**：无关键控件被遮挡；无需横向滚动才能完成核心动作；对话框可关闭；触控目标可操作。

### UX-003 重复点击和网络抖动（P0）

**步骤**：对创建 Space、添加成员、批准 ChangeSet 和授权连接分别进行快速双击；在一个非关键保存动作中模拟短暂断网后恢复。

**预期**：不会创建重复资源或重复发布；按钮有进行中状态；恢复后结果明确，不出现永久加载。

### UX-004 错误信息安全（P0）

**步骤**：触发无权限、无效输入、已删除资源和网络失败。

**预期**：提示说明用户可采取的下一步；不显示堆栈、SQL、绝对服务器路径、Token、Cookie 或内部配置。

## 16. 立即停止条件

出现以下任一情况时停止全部写测试：

1. 测试账号访问到真实用户或非测试 Space 数据。
2. Viewer、非成员、已移除成员或撤权 Agent 仍可写入。
3. 密码、Token、Cookie、安装凭据、服务器路径或内部堆栈泄露。
4. 测试操作导致生产首页、登录或健康接口异常。
5. 删除、审核或同步影响到名称不以 `3PT-` 开头的资源。
6. 单次动作持续生成重复 Agent、Space、页面、Run 或 ChangeSet。
7. 正式知识发生未经确认的静默覆盖或删除。
8. 测试资源无法通过正常产品能力清理。

测试方应记录发现时间、角色、最后一步操作、影响范围和截图，停止继续复现，等待系统负责人决定。

## 17. 缺陷等级

| 等级 | 定义 | 示例 |
|---|---|---|
| S0 阻断 | 生产不可用或大面积数据损坏 | 全站不可访问、无法登录、跨 Space 批量破坏 |
| S1 严重 | 越权、泄露、认证绕过或静默覆盖 | 非成员读写、Token 泄露、撤权后继续发布 |
| S2 主要 | 核心业务流程不能完成 | 无法建 Space、无法保存页面、无法审核或同步 |
| S3 一般 | 非核心功能或体验错误 | 局部布局、次要筛选、非阻断文案错误 |
| S4 建议 | 不影响正确性的改进建议 | 操作提示、视觉一致性和效率优化 |

每个缺陷必须包含：标题、等级、环境、角色、前置条件、复现步骤、预期、实际、复现概率、证据、涉及的 `3PT-*` 资源和清理状态。

## 18. 清理清单

按以下顺序清理：

1. 完成或取消所有测试 Run、同步会话和待审核 ChangeSet。
2. 删除/归档所有 `3PT-*` Source、页面和关系。
3. 撤销测试 Agent 的所有 Space Grant 和凭据。
4. 从三个隔离客户端卸载测试 `agentwiki` 配置并删除隔离 HOME。
5. 删除或撤销所有 `3PT-*` Agent。
6. 从测试 Space 移除用户 B/C。
7. 删除所有 `3PT-*` Space。
8. 管理员 D 软删除专用测试用户 A/B/C；D 的处置由系统负责人执行。
9. 重新登录管理员 D，确认用户状态正确且导航中无残留测试资源。
10. 使用唯一标识全局搜索，确认不存在可访问残留。
11. 复查首页、登录和 `/api/health`。

输出《遗留测试数据清单》。正常验收时该清单必须为空；任何无法清理项按至少 S2 登记。
